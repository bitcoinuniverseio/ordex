HTTP API reference

Small, explicit endpoints for a shared orderbook.

All endpoints are served by the Ordex gateway selected by the market or user. Requests are ordinary JSON over HTTPS; node credentials remain behind the gateway.

Conventions

Base URL examples use https://gateway.example/api/ordex. Query and body values must be treated as untrusted market evidence until a gateway returns verification state. Responses are JSON. A marketplace may apply its normal origin authentication and rate limits outside this contract.

Artifact accessRaw PSBTs are requested through explicit review routes, not the default list projection.
NetworkEach gateway operates against one configured Bitcoin network at a time.
MutabilityOrder edits are new revisions; an original artifact is never silently changed.

Health and catalog

GET/health

Reports whether Ordex is active and which verification dependencies are configured. Use this to label a gateway before presenting inventory as locally verified.

GET/catalog

Lists known protocol templates and their settlement capabilities. Use it to populate protocol filters and explain whether a listing is PSBT-handoff capable or an external settlement intent.

GET/orders/:id

Returns a single review projection, including its evidence and verification details. Use a separate artifact route when the UI must deliberately show the raw PSBT.

Import an order artifact

POST/orders/import

Indexes a user-provided PSBT artifact with market metadata. Import is not settlement; the gateway parses and classifies the evidence before it appears as live inventory.

{
  "psbt": "cHNidP8BA...",
  "protocolId": "ordinals",
  "token": "Example collection",
  "side": "ASK",
  "quotedPriceSats": 250000,
  "source": "direct"
}

The exact supported metadata fields are discoverable through /catalog. A client should display the returned safety classification and state, not infer either from the requested fields.

Prepare and import a signed Nostr event

GET/orders/:id/nostr-envelope

Returns the unsigned kind-802 event for a current order. The browser sends this envelope to a NIP-07 signer; the gateway never signs on behalf of a user.

POST/orders/openordex-event

Accepts a signed event. The gateway rebuilds canonical serialization, verifies its identifier and Schnorr signature, normalizes supported tags, then indexes it as signed evidence.

Relay delivery and gateway indexing are separate acknowledgements.

First, a selected relay must accept the signed event. Then, the active gateway independently verifies and indexes the same event. A robust UI reports both outcomes.
