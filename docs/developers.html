Protocol 1.2 · Developers

Every state change. One envelope. Three transports.

Every public state change in an Ordex gateway becomes one immutable ordex-event/v1 envelope, produced by the transactional outbox at the exact database commit that changed the aggregate. Nothing reconstructs history from websocket chatter or in-memory activity, so replay is deterministic and reversal is explicit.

The envelope

One envelope per state change, everywhere. The fields are stable, and the verifier refuses envelopes that break them.

FieldWhat it carries
idA globally unique uuid. Deduplicate deliveries on it.
typeThe event type, named ordex.<family>.<name>, such as ordex.order.settled or ordex.swap.matched.
schemaVersionCurrently 1.
networkmainnet, testnet, signet, or regtest.
sequenceA monotonic per-network positive integer that never decreases. This is the replay cursor.
aggregateThe type, id, and version of the thing that changed.
observedAtWhen the change was observed.
checkpointThe chain height and block hash the event was observed at, so a consumer can judge freshness.
statusMarks the event as current, or as reverted. Only a reverted event may carry revertedEventId, and it must name the event it reverses; an event cannot reverse itself.
payloadThe public payload. No private wallet data, no xpub, no address the policy does not allow, and no private swap terms.
artifactDigestsDigests of the artifacts this event concerns, so you can pin exactly what you acted on.
traceIdA trace id that reveals no private user information.

Publication targets p95 under two seconds from the authoritative database commit. There are no silent gaps: a gap is a bug, and reconnection replays from the acknowledged id.

Transports

Two streaming transports carry the same envelopes, and webhooks push them to your own endpoint.

GET/api/ordex/events/stream

Server-sent events for resilient browser and server consumption. The SSE id field carries the event id; sending Last-Event-ID resumes exactly after it. Heartbeats keep idle streams open through proxies.

WS/api/ordex/events/ws

WebSocket for multiplexed, high-volume consumers: one connection, many filters, cursor resumption, bounded buffers, and slow-consumer disconnection with a resumable cursor.

Both transports filter by network, protocol, collection, event type, and aggregate, replay deterministically from the acknowledged cursor, and deliver at least once so an id-deduplicating consumer observes exactly-once effect. Retention is at least seven days.

Signed webhooks

A subscription registers an HTTPS endpoint and the event families it wants. Creation returns the signing secret exactly once; storage keeps only a hash, and the endpoint answers a challenge before activation. Each delivery POSTs one envelope with this header:

X-Ordex-Signature: t=<unix>,d=<deliveryId>,v1=<hex> v1 = HMAC-SHA256( key = subscription secret, message = <timestamp>.<deliveryId>.<sha256(body)> )

Verify it in constant time, with a five-minute timestamp tolerance by default, and always against the exact raw body string you received. The SDK and verifier/events.js expose the same signer and verifier your endpoint needs.

import { verifyWebhookSignature } from '@bitcoinuniverse/ordex-sdk'; const verdict = verifyWebhookSignature({ header: req.headers['x-ordex-signature'], // t=...,d=...,v1=... secret: process.env.ORDEX_WEBHOOK_SECRET, // shown once at subscription time body: rawBody, // the exact string that arrived }); if (!verdict.ok) return res.status(400).send(verdict.code);

Delivery is at least once, with exponential backoff, bounded retries, dead-letter state, per-attempt history, manual replay, idempotency ids, and secret rotation with a bounded verification overlap. The delivery worker is isolated from internal infrastructure and hardened against SSRF, DNS rebinding, private-address destinations, unbounded redirects, oversized responses, and endpoint-induced resource exhaustion.

Cursors, never offsets

Replay order is the sort key network:sequence:id. It is deterministic, and consumers resume from it. There is no offset pagination anywhere in the event surface, because an offset into a changing history is a silent lie. Keep the last id you processed, reconnect, and resume from it; retention of at least seven days gives you room to come back.

Historical APIs

Event history, current orders, order history, public swaps, manifests, Counterparty assets, activity, checkpoints, reorg events, asset-state proofs, market snapshots, and bounded NDJSON or compressed CSV exports are all keyset paginated. Every response names its network, checkpoint, freshness, authority, and proof digest. No unqualified number is ever returned where current state could be assumed.

Read-only MCP tools

For local agents and editors, the gateway exposes a read-only MCP surface. Every tool is a read that mirrors one keyset API and returns the same freshness fields, so an agent can look but never touch:

  • List and replay ordex-event/v1 envelopes from a cursor, filtered by family, network, or aggregate.
  • Read current orders, order history, and public swaps with their lifecycle states.
  • Read collection manifests and check a membership proof against a member identity.
  • Read heritage attachment records, including authority readiness and ledger hashes.
  • Read chain checkpoints, reorg events, asset-state proofs, and market snapshots.

No tool signs, builds a transaction, holds a credential, or writes anything. Mutations stay in your own client, behind your own wallet.

Rate limits

Reads and writes each carry a rate budget per client, and writes are always rate limited. A limited request answers with the gateway's standard error envelope stating why and when to retry, rather than hanging or dropping work. The typed client retries reads for you and never retries a write, because the gateway does not deduplicate writes. Design for the envelope: deduplicate events by id, resume from cursors, and treat every read as a snapshot with a named checkpoint.

SDK quickstart

The typed client is generated from the OpenAPI contract, uses your own fetch, holds no keys, signs nothing, and broadcasts nothing.

import { OrdexClient } from '@bitcoinuniverse/ordex-sdk'; const ordex = new OrdexClient({ baseUrl: 'https://bitcoinuniverse.io' }); const health = await ordex.getHealth(); for await (const order of ordex.iterateOrders({ protocol: 'runes' })) { console.log(order.id, order.quotedPriceSats, order.actionability); }

Amounts arrive as decimal strings exactly as the wire carries them; parse them with BigInt when you need arithmetic.

Verify it yourself

  • Check any envelope against the reference verifier at verifier/events.js: sequence monotonicity, checkpoint shape, and reverted-event pairing.
  • Replay conformance/event-vectors.json for the refusal cases.
  • Read the streaming contract, channels, and payload schema in spec/asyncapi.json, and the prose in spec/events.md.
  • Recompute the webhook HMAC over timestamp.deliveryId.sha256(body) yourself before trusting a delivery.

Events are how SafeOps operations, swaps, heritage attachments, and provenance report every transition, so one envelope format covers the whole protocol.
