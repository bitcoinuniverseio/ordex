Portable order evidence with local chain verification.

An Ordex order is not a promise from a marketplace. It is a PSBT artifact plus source evidence, local verification results, protocol metadata, and a clear lifecycle.

Nostr inventory event

Ordex uses an OpenOrdex-compatible Nostr kind: 802 event. The event content is the base64 PSBT. The event is first prepared by the gateway, then signed by the user's NIP-07 extension, and only then relayed.

{
  "kind": 802,
  "created_at": 1730000000,
  "tags": [
    ["n", "mainnet"],
    ["t", "sell"],
    ["s", "250000"],
    ["d", "ordex_…"],
    ["protocol", "ordinals"],
    ["token", "Example collection"],
    ["i", "<inscription-id>"],
    ["u", "<txid>:0"]
  ],
  "content": "<base64-psbt>"
}

After signing, the event includes id, pubkey, and sig. The gateway rebuilds canonical Nostr serialization and verifies the Schnorr signature before accepting it as signed source evidence.

Order lifecycle

StateMeaning
PENDING_NODECore is unavailable, misconfigured, syncing, or has not verified inputs.
PENDING_ORDThe input is available but the claimed inscription location is not yet verified.

MEMPOOL_CONFLICTEDAt least one input is spent or unavailable to the local node.
REJECTEDArtifact parser/safety classification blocks the profile.
WITHDRAWNRemoved from local Ordex inventory. It is not an on-chain cancellation.

Verification is layered

Artifact

Strict PSBT parse

Standard base64, compact-size map parsing, duplicate-key rejection, digesting, and deterministic input evidence.

Bitcoin

Current UTXO check

Bitcoin Core's gettxout determines whether inputs remain available at verification time.

Ordinal

Asset location

The local ord endpoint confirms an optional claimed inscription remains at its claimed outpoint.

Verification is time-bound evidence, not a guarantee about the next block. Every consumer should display the most recent check time and safety classification.

Protocol templates

The catalog includes every market currently exposed by Ordex. Each template says whether it supports a Bitcoin PSBT handoff or requires external settlement.

  • PSBT handoff: Ordinals, BRC-20, Runes, Alkanes, ARC-20, OP_RETURN families, TAP, DMT, UNAT, Names, Bitmap, DUST20, and related Bitcoin markets.
  • External settlement: TAP-DOGE, DRC-20, Doginals, Stamps, and SRC-20. These are explicit p2p intents, not fake Bitcoin PSBT support.
  • Immutable edits: a rebuild creates a new local draft revision. The source artifact is never modified.

Security boundaries

Ordex is not a wallet.

It does not request seed phrases, access wallet keys, sign a PSBT, fund a transaction, combine unrelated PSBTs, or broadcast a transaction. Nostr signing remains inside the user's extension after an explicit user action.

Those constraints are deliberate protocol boundaries, not a missing marketplace feature. They make it possible for many venues to use the same inventory without a single venue becoming the custodian of every trade.
