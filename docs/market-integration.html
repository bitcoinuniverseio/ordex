Market integration

Make inventory portable without giving up verification.

Use Ordex as a discovery and review layer: your market can provide a default verification gateway while every user retains the option to select an independent one.

Connection modes

DEFAULT

Your market gateway

Leave the connection field empty. The client resolves to the Ordex endpoint operated by your market.

INDEPENDENT

User gateway

Accept a credential-free Ordex URL from the user and store only that local preference in their browser.

NEVER DIRECT

Node credentials

A browser does not call Core RPC or ord with credentials. Those private services remain behind the chosen gateway.

Inventory contract

The list projection is intentionally small, stable, and safe to filter. A market asks for a detailed artifact only after the user opens an explicit review action.

Signed distribution flow

  1. Create or attach a reviewed order artifact.The market collects source context but does not treat it as settlement truth.
  2. Request a gateway envelope.The active Ordex gateway produces a canonical unsigned kind-802 event for the current order.
  3. Prompt the publisher's NIP-07 signer.The user sees and approves the signature request in their own Nostr extension.
  4. Require a relay acknowledgement.Send the signed event to selected relays and count publication as successful only after a matching OK.
  5. Index the same signed event.Post it back to the active gateway so it verifies the id and Schnorr signature before exposing it as signed evidence.

Market experience requirements

01

Make verification legible

Display state, check time, safety classification, protocol, token, and source near the price.

02

Keep uncertainty honest

PENDING_NODE and PENDING_ORD are useful evidence states, not errors to hide behind an optimistic label.

03

Explain local withdrawal

Withdrawing removes the local index projection. It does not spend an input or erase copies of a prior public event.

04

Separate review from settlement

Ordex tells a user what is currently observable. A wallet remains responsible for any user-approved transaction action.

Filters and sorting that help real buyers

Expose filters that let users compare verified evidence rather than only collection names. Good defaults are protocol, token, state, side, safety, and source. Pair them with ascending/descending price, newest, recently verified, and most recently updated sorts.

Safety is a first-class filter.

Public/raceable asks and targeted/review profiles should never look identical. Put the safety badge in the main result row, not inside a tooltip.

Settlement limits

Bitcoin-family templates accept a user-created PSBT handoff. Dogecoin and Counterparty/Stamps templates are clearly marked as external settlement intents until a matching chain-specific verifier is available. Ordex does not custody a wallet, combine PSBTs, or settle a trade.
