Operator guide

Run the verification gateway your market can trust.

Ordex is the thin gateway between market inventory, Bitcoin Core, local ord, and signed Nostr events. It needs no wallet and no signing key.

Topology

Place Ordex beside your own fully-synced Core node and ord index. The browser speaks only to your Ordex HTTP API. Core RPC authorization remains private to the gateway process.

Environment

Start from the repository's .env.example. Mainnet is the default network; signet and regtest remain useful for isolated testing.

ORDEX_ENABLED=true
ORDEX_NETWORK=mainnet
ORDEX_CORE_RPC_URL=http://127.0.0.1:8332
ORDEX_CORE_RPC_AUTH=<basic-auth-value>
ORDEX_ORD_URL=http://127.0.0.1:8080
ORDEX_STORE_PATH=./data/ordex/journal.json

Do not place the Core authorization value in browser configuration, source control, or Nostr events. A public market client only needs the Ordex gateway URL.

Core RPC policy

Grant the Ordex process only the methods it uses. The service never calls wallet, signing, broadcasting, or UTXO-mutating RPC methods.

MethodPurposeEffect
getblockchaininfoNetwork and synchronization checkread only
gettxoutVerify each PSBT input remains unspentread only
testmempoolacceptOptional preflight of a user-supplied final transactionread only

Health checks

GET /api/ordex/health reports whether Core and ord URLs are configured. A fully useful gateway needs both. If Core is unavailable or still syncing, inventory remains visible but orders report pending node validation rather than a false live status.

Expose Ordex, not Core.

When users bring their own verification, they point the browser at their own self-hosted Ordex gateway. Do not ask a browser for Core RPC credentials or expose Core directly over a public origin.

Operations

  • Persist the journal on durable storage and back it up as ordinary market metadata.
  • Keep Core and ord synchronized before advertising a verified inventory status.
  • Use a reverse proxy with normal application authentication/rate limits where your market needs them.
  • On maintenance, set ORDEX_ENABLED=false; no wallet or node state is modified.
  • Run your own Nostr relay policy separately. Ordex clients publish only to relays selected by the user.
