Quickstart

Pick your path. Keep your verification independent.

A marketplace, an operator, and a collector use Ordex differently. The common rule is simple: browsers speak to an Ordex gateway; a gateway speaks to the node and indexer it is configured to trust.

Before you begin

Decide which gateway will verify the inventory you see. A market can provide a default gateway. An advanced user can choose a self-hosted one. The browser stores only a gateway URL and relay URLs; it never needs Bitcoin Core credentials.

Marketplace: add Ordex inventory

  1. Operate or select a gateway.Configure your Ordex API endpoint alongside your current market API.
  2. Render verification state.Show protocol, token, source, safety classification, and the most recent local verification state beside every listing.
  3. Expose connection choice.Leave the gateway field empty for your default. Permit a user to replace it with their own Ordex gateway URL.
  4. Publish only after relay acknowledgement.Request the unsigned event, let the user sign it in a NIP-07 extension, then require an OK from at least one configured relay.

Read the market guide

Operator: run the verifier

  1. Synchronize Core and ord.Core supplies current UTXO evidence. ord supplies ordinal asset-location evidence.
  2. Configure an Ordex gateway.Set its network and private local service URLs. Keep Core authorization inside the gateway environment.
  3. Check health before advertising inventory.A healthy gateway identifies the expected chain and has a reachable indexer. Pending conditions are honest states, not failures to hide.
  4. Expose only Ordex.Put the gateway behind your normal application proxy. Do not expose Core RPC or the ord endpoint to browsers.

Read the operator guide

Collector: choose a connection

  1. Open the connection panel.Leave the gateway empty to use the marketplace default, or enter a credential-free URL for your own Ordex gateway.
  2. Add relay URLs.Use one wss:// relay URL per line. They remain a browser-local preference.
  3. Review an order.Inspect its source, current verification state, input evidence, protocol metadata, and public/raceable classification before taking action.
  4. Publish portable inventory.When publishing, your NIP-07 extension shows a signing prompt. Ordex receives the signed event and verifies it; it never receives your Nostr private key.

Use an external wallet for Bitcoin settlement.

Ordex is an evidence and routing layer. Any funding, PSBT signing, or Bitcoin broadcast remains in a wallet application under the user's explicit control.

Success checklist

  • Your gateway reports the intended Bitcoin network.
  • The listing shows an explicit verification state rather than an assumed live state.
  • The event is signed by the publisher's NIP-07 extension.
  • At least one selected relay accepted the signed event.
  • The active gateway indexed the same signed event after signature verification.
